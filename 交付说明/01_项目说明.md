# 01 项目说明

## 项目定位

GridFlux 是面向算力网场景的高速可靠数据传输底座。它对外提供 GridFTP-like 的控制面子集，对内使用自研 framed chunk 数据传输、manifest 恢复、CRC32C 校验和多连接传输。

一句话概括：

> 对外像 GridFTP，对内是 GridFlux 自己的可靠高速传输引擎。

## Alpha RC 已实现能力

| 模块 | 状态 | 说明 |
|---|---|---|
| 单文件上传 | 已完成 | 支持 `STOR`，内部走 framed file data channel |
| 单文件下载 | 已完成 | 支持 `RETR` |
| 断点续传 | 已完成 | 使用 `REST GFID:<transfer_id>` 和 manifest 恢复 |
| 校验 | 已完成 | 默认 CRC32C，可选 `none`，支持 hardware/software backend |
| 控制面 | 已完成项目子集 | `USER/PASS/TYPE I/SYST/FEAT/PWD/NOOP/QUIT/EPSV/PASV/STOR/RETR/REST/SIZE/MDTM/CWD/CDUP/LIST/NLST` |
| 目录传输 | Alpha 可用 | 支持目录 upload/download/resume 和文件级并发 |
| Token auth | Alpha 可用 | `anonymous|token`，默认 anonymous |
| Control TLS | Alpha 可用 | `--tls-mode off|required`，默认 off |
| Data TLS | Alpha 可用 | `--data-tls-mode off|required`，保护 STOR/RETR framed file data channel |
| 可观测性 | Alpha 可用 | JSONL event log、稳定错误码、demo/gate summary |
| Release gate | 已完成 | quick/full gate、artifact manifest、远端 verify |
| Alpha RC | 已完成 | 一键 alpha release candidate 脚本和报告 |

## 核心架构

```text
GridFTP-like control plane
  -> Session / Manifest
    -> Framed STOR/RETR transfer engine
      -> Checksum
      -> File IO backend
      -> Optional TLS socket wrapper
```

目录传输不是单独的数据协议，而是：

```text
tree manifest
  -> per-file STOR/RETR
    -> per-file manifest / checksum / resume
```

## 默认策略

默认策略保持保守可靠：

| 配置 | 默认值 |
|---|---|
| auth mode | `anonymous` |
| tls mode | `off` |
| data tls mode | `off` |
| file IO backend | `posix` |
| final verify policy | `full` |
| manifest flush policy | `every_n_chunks` |
| preallocate | `off` |
| posix write strategy | `auto` |

## 适合用于

- 算力网高速传输原型演示。
- GridFTP-like 控制面研究。
- 多连接 framed 数据传输实验。
- manifest 断点续传可靠性验证。
- TLS/token/auth/release gate 的 alpha 级工程闭环展示。

## 不适合直接用于

- 生产环境直接暴露公网。
- 替代完整 GridFTP/GSI。
- 需要完整 POSIX metadata 保真的目录同步。
- 100G 生产吞吐承诺。
