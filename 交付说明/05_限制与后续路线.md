# 05 限制与后续路线

## 当前限制

CPNetFlux Alpha RC 是完整原型，不是 beta/production。

主要限制：

| 限制 | 当前行为 |
|---|---|
| GSI | 未实现完整 GSI |
| 生产证书体系 | 仅有 alpha TLS 配置，不含生产 CA/证书生命周期管理 |
| LIST/NLST data TLS | listing 命令在 control TLS 内受保护，但 passive listing data channel 仍是明文 |
| raw FTP recursion | 不支持 raw FTP recursive transfer |
| 目录 metadata | 不保留 owner/group/xattr/ACL/空目录 |
| 100G | 未完成 100G 跑满验证 |
| 广域网 | QUIC/FEC/高 RTT/丢包优化未正式展开 |
| 观测系统 | 当前是本地 JSONL event log，不是集中式 metrics/logging |

## 当前完成度判断

| 层级 | 完成度 |
|---|---|
| Alpha 原型 | 约 99%，已可作为完整原型交付 |
| Beta | 未开始 |
| Production | 未开始 |

## 后续路线建议

### Beta 1A 性能专项

目标：回答系统能否向 100G 靠近。

重点：

- 1GiB、4GiB、16GiB 大文件矩阵。
- connections 1/2/4/8/16。
- POSIX vs io_uring。
- checksum crc32c vs none。
- TLS/data TLS off/on。
- CPU、磁盘、网络、Dirty/Writeback、iostat 阶段拆解。

### Beta 1B 生产安全

目标：从 alpha token/TLS 走向更正式的安全模型。

重点：

- mTLS。
- 证书信任链。
- 证书权限和轮换。
- GSI 兼容性评估。
- 用户/路径/权限模型。

### Beta 1C 目录语义

目标：让目录传输更接近真实同步工具。

重点：

- mtime 保真。
- owner/group 策略。
- xattr/ACL 策略。
- 空目录保留。
- symlink 策略。
- overwrite/diff/sync 模式。

### Beta 1D 运维观测

目标：让系统能长期运行和定位问题。

重点：

- Prometheus/OpenTelemetry。
- 集中式日志。
- 多小时/多日 soak。
- 自动报告。
- 失败现场保留和清理策略。

### Beta 1E 广域网实验

目标：高 RTT 和丢包场景。

重点：

- QUIC。
- FEC。
- 拥塞控制实验。
- RTT/loss 仿真。

## 推荐下一步

如果项目目标仍是“高速可靠数据传输底座”，建议优先进入 **Beta 1A 性能专项**。现在功能闭环已经很完整，最需要证明的是吞吐上限和瓶颈位置。
