# 2026-11-04 CPNetFlux 性能路线决策

## 决策

性能主线切换为：先完成 R770 单链路原生 RDMA 与真实文件的可复现端到端基线，再按实测瓶颈优化。详细阶段、指标和目标见 [单链路 100G 性能提升路线](../tasks/2026-11-04-performance-roadmap.md)。

本决策取代 2026-10-29 S0-S8 在 `docs/ROADMAP.md` 中作为“当前下一步”的状态。S0-S8、旧 P0/Phase 4 任务及结果仍作为历史实现和证据保留；只有新基线显示相应问题时才重新纳入当前任务。

## 依据

- 输入提交 `a4ae9963db17bc061aadcfa8d95d13de6c86849f` 已固定 R770 双机 E2E 基线范围，但验收尚未完成。
- direct bench 与原生硬件基准很高，不代表真实文件路径达到同等吞吐；post-RNR-fix 文件矩阵是当前待补证据。
- 当前注册接收池和多连接 RSS 成本显著，队列、CQ 等待、复制、校验、文件提交必须分别测量。
- 开题设计中的三阶段流水线、SR-Dispatch/BAP、adaptive microbundle 是候选方案；profiling 与 native/fixed 对照是进入实现的门槛。
- R770-1 当前只有一个 100GbE/RoCE 端口，不具备验证 10×100Gbps 汇聚的拓扑。

## 工作优先级

1. 完成 `docs/tasks/2026-11-04-r770-rdma-e2e-baseline-01.md` 的固定提交、双机同配置构建、链路和真实文件矩阵。
2. 根据证据定位长文件瓶颈；先处理队列/建连/资源，再考虑三阶段数据流水线。
3. 大文件吞吐稳定后，独立测量 small-file `T_ready`，对比 native per-file、fixed microbundle、adaptive microbundle。
4. 只有观测到服务率异质性和调度拖尾，才实施 SR-Dispatch。
5. 单端口完成稳定性验收后，另行规划多端口/1Tbps。

## 性能目标

10–20 Gbps（首个真实文件里程碑）、30–50 Gbps（单大文件并行 range 中期目标）、70–85 Gbps（单端口冲刺目标）是路线目标，不是预测或承诺。报告同时列 payload steady 与含 setup/commit 的 task rate。85–90 Gbps 仅为有证据后的极限探索；不承诺应用有效吞吐必然达到 100Gbps，也不由单端口实验推导 1Tbps。

## 执行状态

路线制定时只批准计划；后续执行事实以任务结果为准，不代表目标已达成。

2026-11-04 基线收口：48 个样本中 42 通过、6 个 64 GiB 下载失败，见 [结果](../tasks/2026-11-04-r770-rdma-e2e-baseline-01-result.md)。旧“下一步完成采样”状态失效；下一步为 [V3 缺失块握手修复](../tasks/2026-11-04-v3-resume-mask-01.md)。只合并相邻 on-wire 缺失区间并明确拒绝超限碎片，不变更 V3 编码、帧上限、内部逐块校验与原子发布语义。

64 GiB 收全后的长校验收尾超时独立归因；在文件完整性门补齐前，不开展接收池/CQ/流水线优化或宣称性能验收通过。
