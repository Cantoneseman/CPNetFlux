# 云端优先开发与 GitHub 分阶段备份

- 日期：2026-09-24
- 状态：2026-10-09 按用户要求更新为深圳根目录单人串行开发；取消迁移前置条件
- 适用：00 总指挥及 01–05 所有长期角色、后续新聊天和续接中的旧聊天
- 范围：CPNetFlux 源码、协作文档、任务管理、构建、测试、结果分析和实验

## 决定

CPNetFlux 在深圳 `/root/projects/CPNetFlux` 根目录直接开发。同一时刻只有一个开发写入者，由 00 总指挥串行完成实现、测试、提交和实验；既有角色聊天保留，不默认并行派单。用户明确取消迁移门与强制独立 worktree 要求。上海只作为跨域传输对端，不建立第二个权威开发副本。Windows 用于连接、查看和备份，不作为日常源码或 Git 工作区。

每个完成阶段在当前开发分支提交明确文件，并推送到已核实的 CPNetFlux GitHub remote；不为每个小步骤额外创建分支。记录 commit SHA、版本/改动说明、push 退出状态，并核对远端 SHA。需要恢复时选择 GitHub 已备份版本，先保留当前修改，再恢复明确文件或撤销指定提交。GitHub 只备份已提交并推送的内容，不包含未提交修改、大 payload、全量日志或凭据；外部证据保留路径和 SHA-256。

所有提交必须精确列出文件，禁止 `git add .` 混入其他任务内容。不得提交私钥、口令、token、运行时凭据、构建目录或大 payload。推送失败、远端未核实、权限不可用或 SHA 不一致时，明确报告备份未完成，保留当前状态并给出具体阻塞；不得把本地 commit、云端磁盘副本或聊天中的回执说成 GitHub 备份。

## 2026-10-09 流程变更

用户明确要求根目录直接开发、单人串行和 GitHub 阶段备份。原 `CLOUD-GITHUB-01` 迁移验收及强制 worktree 不再是开发依赖，旧门禁已失效；不把取消门禁说成历史迁移验收通过。

`dirty` 仅表示未提交修改，不是停止开发的理由。先理解本次目标文件已有内容，再继续修改；保留无关文件，不擅自 reset/clean。恢复操作按明确的 GitHub 提交和文件范围执行，不自动清空根目录。

两端 `/root/projects/GridFlux-Beta` 仍是历史证据目录，不覆盖或清理；`/root/projects/CPSS(DCC)` 保持受保护。已有服务和实验不因工作方式变更而被停止。比较 GridFTP 前仍须刷新并验证 GSI proxy、核查两端空间及服务；测试和实验的事实要求保持有效。

## 为什么按阶段备份

“操作完备份一次”在项目执行中按可审查的任务阶段落实：文档或规格交付、代码实现阶段、测试验收阶段、实验计划/结果阶段各自形成明确 commit 和 GitHub push。长构建或实验运行期间不频繁制造无意义提交；在运行前先推送可恢复的任务定义/脚本版本，在结束后推送结果报告与索引，原始大数据按证据流程保存并校验。失败也要留下带清楚状态的记录，不能把失败结果改写为通过。

## 覆盖与不覆盖

本决定覆盖旧角色 prompt、入口说明、历史回执和聊天记忆中“Windows 本地是日常源码/Git/分析工作区、云端只做构建实验”的流程描述；与之冲突时，以本决定、更新后的 `AGENTS.md`/`ENVIRONMENT.md` 和当前任务单为准。它不更改性能目标、实验准入门、云端保护路径、研究结论，也不授权删除数据、停止未知进程、降低认证/TLS 或执行未经任务单列明的外部写操作。
