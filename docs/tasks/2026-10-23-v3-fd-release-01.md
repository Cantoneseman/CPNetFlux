## 解决的问题

批次 context 为完整性审计保留已完成的 FileTransaction，但每个事务也一直持有 BufferedFileWriter 和 PosixFile。目录传输大量小文件时，这会让已提交文件的 FD 数随文件数增长，触碰默认 1024 的 RLIMIT_NOFILE，进而导致后续文件或 manifest 无法打开。

## 实现

FileTransaction::commit() 在输出成功发布、committed manifest 写入完成并清理临时路径后，先销毁 writer，再关闭事务持有的输出文件。审计仍保留事务的身份和 manifest 状态；verifyPublished() 在最终审计时按需只读打开输出，并在本次检查结束时关闭，不改变校验、提交或恢复语义。

## 验收

新增真实 V3 persistent socketpair 回归测试：将测试进程 soft RLIMIT_NOFILE 降为 1024，传输 2048 个各 64 KiB 文件，context 保持存活，检查传输后目标目录 FD 数为 0，再执行完整性审计并确认审计后仍为 0。

先在未修复代码上运行该测试，接收端因 FD 累积而报 open manifest failed，发送端也报源文件打开失败；修复后，同一测试在约 1 秒内完成，传输、审计及边界文件大小检查全部通过。
