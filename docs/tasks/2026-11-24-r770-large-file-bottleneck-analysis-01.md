# R770 大文件瓶颈定位实验 01

日期：2026-11-24  
固定运行时提交：`34ded615ea72ea2ee805b08075d39d945288f66d`  
实验目标：区分接收写入、应用 pacing、发送 CPU 和 TCP/网卡稳定性对大文件吞吐的影响。

## 范围与非目标

本轮只做诊断和实验驱动配置，不修改 CPNetFlux C++ 运行时、协议格式、CRC32C、租约、恢复语义、网卡 RX/TX ring、IRQ、RSS、MTU、offload、THP 或 swap。5 GiB 结果只作为内部瓶颈证据，不写入年度对比报告。年度报告保留独立的 1 GiB 对比口径。

固定环境为 R770-2↔R770-1 的 `192.168.100.2/.1`、`eno17095np0`、四条 TCP 数据流、V3 worker reuse、256 KiB DATA、1 MiB 恢复 chunk、每 16 块 checkpoint、CRC32C/verified_chunks、tmpfs、压缩关闭、`RX/TX=1024/1024`。任何网卡、内存或完整性门失败都拒收样本并停止后续矩阵。

## 实验矩阵

| 组 | 接收写入 | pacing | 目的 |
|---|---|---|---|
| A | inline mmap | 1.5 GB/s/流 | 当前 5 GiB 内部基线 |
| B | pwrite | 1.5 GB/s/流 | 接收写入路径对照 |
| C | inline mmap | off | 判断应用 pacing 是否限制发送速率，观察网络压力代价 |
| D | inline mmap | 1.0 GB/s/流 | 低速控制对照，判断吞吐与 CPU/重传的关系 |

每个候选先跑一个 512 MiB 完整任务并记录接收端细分 profile。通过资源、接口、SHA、协议终态和清理门后，再跑一个 5 GiB 完整任务。A 使用已完成的 `2026-11-24-r770-receive-cost-01` 和 `2026-11-24-r770-annual-5g-independent-reruns` 作为历史对照，当前实验只补 B/C/D。每个新增候选最多一个 512 MiB 样本和一个 5 GiB 样本，不根据单次速率挑选样本。

## 观测与判定

主要指标是 `T_ready` 和有效 Gbps。并列记录发送端、接收端进程 CPU 秒，主机忙碌 CPU 秒/GiB，TCP 重传，`rx_missed_errors`、`rx_out_of_buffer`、接口字节，帧数、chunk 校验、外部 SHA 和资源清理。

- 若关闭 pacing 明显提高速率且 CPU/重传或 RX 计数未过门，当前应用 pacing 是主要限制因素，后续优化方向转向自适应 pacing 和发送服务效率。
- 若关闭 pacing 只提高发送压力并触发 RX/重传，接收服务能力或网络排队是当前上限，后续优先做接收 drain/写入交接优化和有界背压。
- 若 pwrite 相对 mmap 显著增加接收写入 CPU并降低完整任务速率，mmap 写路径保留为大文件明文候选，后续优化聚焦映射窗口、写入批次和接收线程交接。
- 若所有候选都接近且 CPU/网络门通过，瓶颈需要转向帧读取、发送系统调用、连接调度或 TCP 栈，不能继续只改接收写入。

单次样本只用于定位方向。正式保留需要同提交重复对照，不能把 profile 样本直接当作性能成绩。5 GiB 使用内存文件系统，不能推出磁盘持久化或原生 RDMA 结果。

## 后续开发准入

完成矩阵后形成一份结果文档，给出单一优化候选、受影响文件、内存预算、正确性回归、停止条件和正式验收矩阵。开发阶段保持一个写入者，先在 R770-1 提交，再同步 R770-2 构建并核对二进制 SHA。若实验被 RX/OOB、资源或环境门阻塞，交付阻塞证据和最小解除条件，不用更换基线绕过停止门。
