## Candidate Contract

`CPNETFLUX_RECEIVER_PAYLOAD_EXECUTION=inline` selects synchronous receiver payload
writes with ownership returned to the same frame buffer after IO. The default is
`queued`. Explicit two-frame write batches and shared writer pools retain their
queued execution and report the actual mode. Both paths call the same writer
routine, including startIo/finishIo, verified chunks, range certification, stage
admission, max-chunks interruption and error draining. No CRC or commit shortcut.

Actual source files: include/cpnetflux/core/io/persistent_tree_transfer.h;
src/core/io/persistent_tree_transfer.cpp; tests/unit/persistent_data_session_test.cpp;
tests/unit/persistent_range_write_test.cpp. Additive timing field:
`receiver_payload_execution` = not_receiver / queued / inline. Inline receiver
pipeline budget/depth/high-water and writer-thread CPU are zero; stage ownership
bounds remain conservative. Frame buffers are reused without a payload copy.

New tests first failed in the original implementation (3/3), then passed (3/3):
upload/download blocked pwrite executes on the receiver thread and cannot publish
before IO; invalid execution configuration creates no checkpoint. Red and green
build/test logs are in the evidence root. Also updated
tests/unit/framed_data_socket_test.cpp: real allocation observations now check the
requested queued/inline mode, with a tighter one frame buffer plus verified-chunk
readback bound for inline execution. The original inline CTest run failed only
the old mandatory-queue depth/high-water expectations in that test; it was not
an integrity or allocation-bound failure.
