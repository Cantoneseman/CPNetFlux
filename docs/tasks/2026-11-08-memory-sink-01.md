# V3 Memory Sink 01：任务范围与结果

日期：2026-11-08  
状态：实验完成；作为内存数据面诊断基线保留，未进入 V3 默认路径。

## 目标

使用现有 cpnetflux-server/client 内存 TCP sink，测量不含文件创建、pwrite、CRC、manifest 和 V3 提交的 CPNetFlux 用户态数据面，解释 raw TCP 与 V3 完整任务之间的差距，并为下一轮单因素优化提供固定基线。

## 输入与固定条件

- 权威代码：R770-1 /home/Su/projects/CPNetFlux；R770-2 只作为构建和传输对端。
- 使用已推送提交 `a2096d1f1c29fce6aab5bcea37db47137cd08ef9`；二进制与 CMake 配置两端一致。
- TCP 数据通道绑定服务端 192.168.100.1，客户端连接该地址；接口 eno17095np0。该路径是 TCP，不称为原生 verbs。
- 证据根目录：/home/Su/experiments/CPNetFlux/2026-11-08-memory-sink-01。

## 实验设计

- 单次总 payload 8 GiB，buffer-size=1 MiB，服务端和客户端均使用用户态缓冲，不创建输出文件。
- 连接数 1、4、8；每组 7 次，交错顺序；保存 client/server stdout、wall time、CPU/RSS、route、接口计数器、内存和 swap 守护证据。
- 只改变连接数；不改内核、MTU、NUMA、TLS、RDMA、socket buffer 或生产服务。
- 结果同时报告 sink throughput、CPU seconds/GiB、CV、raw TCP 对照，以及与 8GiB V3 c4 完整任务的差距。

## 验收门

- 每组 7 次；CV ≤5% 才可用于比较。
- 每次 client/server 均返回 0，发送和接收字节均为 8GiB；期间 MemAvailable ≥12GiB、实验进程 owned swap=0、pswpout 增量=0。
- 记录显式 route 和 eno17095np0 计数器增量；实验结束清理日志之外的进程和所有临时数据。
- 不把 sink 结果称为 V3 文件吞吐、持久化吞吐、RDMA verbs 或 100Gbps readiness。
- 若 sink 达到 raw TCP 的 90% 以上，则下一步分析 V3 文件/提交路径；否则只在 sink 内做一个事件循环候选，候选须新 scope 和单因素门。

## 实验结果

证据目录保留在 `/home/Su/experiments/CPNetFlux/2026-11-08-memory-sink-01`；未生成 payload 文件。21 个正式样本均为 client/server rc=0，发送与接收均为 `8589934592` 字节，实验期间最低 MemAvailable 约 28.10 GiB，所有样本两端 `pswpout_delta=(0,0)`，实验后无残留 sink 进程或临时 payload。

| connections | median Gbps | mean Gbps | CV | 双端 CPU sec/GiB 中位数 | 判定 |
|---:|---:|---:|---:|---:|---|
| 1 | 27.4345 | 28.8850 | 20.04% | 3.47 | 稳定性门未过 |
| 4 | 40.5639 | 40.5197 | 2.95% | 2.89 | 稳定基线 |
| 8 | 40.2047 | 41.9166 | 7.01% | 2.91 | 稳定性门未过 |

raw TCP 四流对照中位数约 89.469 Gbps；4-connection memory sink 仅约 45.34%，因此没有达到 raw TCP 的 90% 事件循环门。4 connections 是本轮唯一同时满足稳定性门的 sink 基线；1/8 connections 只作为诊断证据，不作为候选比较的合格基线。

该结果说明当前差距尚未能归因到磁盘，且继续增加 sink connections 没有收益：4 与 8 connections 几乎相同，1 connection 波动大。下一轮只允许在 sink 内引入一个事件循环候选，不修改 V3 默认文件路径、RDMA、三阶段 writer 或生产服务。
