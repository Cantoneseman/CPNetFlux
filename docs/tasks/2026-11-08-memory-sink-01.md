# V3 Memory Sink 01：任务范围

日期：2026-11-08  
状态：scope ready；尚未开始实验。

## 目标

使用现有 cpnetflux-server/client 内存 TCP sink，测量不含文件创建、pwrite、CRC、manifest 和 V3 提交的 CPNetFlux 用户态数据面，解释 raw TCP 与 V3 完整任务之间的差距，并为下一轮单因素优化提供固定基线。

## 输入与固定条件

- 权威代码：R770-1 /home/Su/projects/CPNetFlux；R770-2 只作为构建和传输对端。
- 使用当前已推送提交 4de8f2b010b5bedab47f35846cc73da747700316；二进制与 CMake 配置两端必须一致。
- TCP 数据通道绑定服务端 192.168.100.1，客户端连接该地址；接口 eno17095np0。该路径是 TCP，不称为原生 verbs。
- 证据根目录：/home/Su/experiments/CPNetFlux/2026-11-08-memory-sink-01。

## 实验设计

- 单次总 payload 8 GiB，buffer-size=1 MiB，服务端和客户端均使用 tmpfs 之外的用户态缓冲，不创建输出文件。
- 连接数 1、4、8；每组 7 次，交错顺序；保存 client/server stdout、wall time、CPU/RSS、route、接口计数器、内存和 swap 守护证据。
- 只改变连接数；不改内核、MTU、NUMA、TLS、RDMA、socket buffer 或生产服务。
- 结果同时报告 task/user-space sink throughput、CPU seconds/GiB、CV、raw TCP 对照，以及与 8GiB V3 c4 完整任务的差距。

## 验收门

- 每组 7 次；CV ≤5% 才可用于比较。
- 每次 client/server 均返回 0，发送和接收字节均为 8GiB；期间 MemAvailable ≥12GiB、实验进程 owned swap=0、pswpout 增量=0。
- 记录显式 route 和 eno17095np0 计数器增量；实验结束清理日志之外的进程和所有临时数据。
- 不把 sink 结果称为 V3 文件吞吐、持久化吞吐、RDMA verbs 或 100Gbps readiness。
- 若 sink 达到 raw TCP 的 90% 以上，则下一步分析 V3 文件/提交路径；否则只在 sink 内做一个事件循环候选，候选须新 scope 和单因素门。

## 非目标

- 不改 V3 默认文件路径、三阶段 writer、协议、RDMA 数据面或生产服务。
- 不提交实验 payload、完整日志或临时脚本到 Git。
- 不在本 scope 内实现内存 sink 到 V3 协议的正式生产接口；本轮只建立诊断基线。
