# Milestone37: Explicit 1 MiB V3 DATA

Input commit: `d26a96ea171fde6c20ca3bdb821635cc5c5ab773`.
Authoritative writer: R770-1 `/home/Su/projects/CPNetFlux`; R770-2 accepts only a fixed commit.

## Scope

Add an opt-in 1,048,576-byte logical V3 TCP DATA frame while retaining the current 65,532-byte default and 262,144-byte candidate. With CRC32C, a maximum 1 MiB frame occupies 1,048,580 wire payload bytes. Preserve 1 MiB recovery chunks, CRC authentication, range/attempt identity, cancellation and resume behavior. Keep control payload at 65,536 bytes and FILE_BEGIN at 8,192 bytes. Use the existing 64 MiB aggregate payload budget; at four lanes and depth two the conservative frame ownership bound is `4 * (2 + 6) * 1,048,580 = 33,554,560` bytes (32 MiB).

## Non-goals

- Do not change default frame size, TLS/RDMA eligibility, TCP receive buffer, checksum, chunk size, storage backend or system network settings.
- Do not raise the aggregate payload or mapped-window budgets.
- Do not claim 8 GiB M1, 40-50 Gbps, 100 Gbps, disk persistence or production readiness from 1 GiB results.
- Do not modify unrelated user changes or historical measurements.

## Acceptance

1. Parser and CLI accept only 65,532, 262,144 and 1,048,576 logical bytes. The 1 MiB option remains restricted to V3 worker reuse, TCP, TLS/compression off, CRC32C and 1 MiB chunks.
2. V3 negotiation echoes selected and maximum DATA capacity. An older peer or unsupported value is rejected before data-channel creation/payload. DATA is accepted only up to negotiated 1,048,580 bytes; control and FILE_BEGIN limits remain unchanged.
3. Conservative stage ownership fits 64 MiB for four lanes/depth two and rejects shapes exceeding that bound before payload allocation.
4. Unit and smoke coverage includes full/tail frame round trip, CRC failure, truncation, cross-chunk rejection, negotiation fallback, interrupted resume, and existing default/256 KiB behavior.
5. On the fixed commit, both R770 builds/tests and binary SHA-256 match before a five-pair interleaved 1 GiB 256 KiB-versus-1 MiB full-task comparison. Preserve all samples and cleanup evidence; do not add instrumentation to timed runs.
6. Run related CTest/script gates, then record the actual outcome in the roadmap/result and push/read back the fixed commit.
