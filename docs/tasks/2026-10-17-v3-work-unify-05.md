# V3-WORK-UNIFY-05：兼容编排收口与取消边界

状态：planned，尚未开始源码实施。依赖 04 的有界重连及双云正确性验收；本任务完成父项 02 仍未收口的兼容编排与取消边界。

## 要解决的实际问题

03/04 已使 persistent dynamic 的 lease 执行与自动恢复可用，不能据此推定显式 static/per-file 以及兼容降级路径都只有一个生命周期 owner。不同分支处理取消、超时、逐文件拒绝及结果回调，容易重复回收租约或让旧回调修改新任务；04 的真实回归已证明过宽的整批 abort 会破坏“单文件失败后继续其他文件”的行为。

目标是在保留兼容行为的同时减少分支内各自推进状态的逻辑，为下一步 LinkSet 统一承载工作提供入口。

## 范围与非目标

1. 盘点单文件、目录 upload/download、persistent/static/per-file 的调用图，区分仅规划与持有 active work 的位置；用文件/函数映射证明实际共同入口。
2. 将仍独立推进 lease 的兼容编排接入 WorkExecutor 与唯一 queue owner，scheduler 仅规划预算；保留已有顺序、逐文件失败继续处理、降级原因和状态输出。
3. 明确 stop claims、取消/超时、shutdown/join、terminal 回调和 lease 释放的唯一顺序；旧 worker/epoch 结果不得修改当前 owner。
4. 同一统计定义覆盖所有路径，保留现有字段兼容；恢复仍由 04 支持范围决定，不因为共享 executor 就宣称 static/per-file 已支持自动重连。
5. 不做十物理链路、RDMA、默认策略调整、生产发布或桌面取消按钮；不更改已验收 manifest 持久化格式。无法复用的路径须明确记录，不能静默降级。
