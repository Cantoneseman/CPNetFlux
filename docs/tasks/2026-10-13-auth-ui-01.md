# AUTH-UI-01：桌面端节点认证闭环

## 任务范围

- 在现有 CPNetFlux 桌面端节点页面增加可操作的认证向导：端点、CA 文件和受保护 token 文件路径的校验、保存、认证检查及逐步结果。
- 复用现有 agent/core 的 TLS、token 和控制面能力；认证结果必须来自真实检查。
- 统一 connection-test 检查状态与 schema，清楚区分配置错误、网络不可达、TLS/凭据失败和后端尚未支持。
- 更新 Linux 安装/使用说明，使首次安装用户知道如何准备节点认证并从桌面端执行检查。

## 非目标

- 不修改传输协议、range/队列语义或核心数据面。
- 不实现 token 明文输入、secret-store 管理、管理员凭据或单文件传输。
- 不进行性能实验、跨域实验、桌面端大规模重设计，也不修改其他项目。
- 不把“端口可达”或本地文件可读误报为远端认证成功。

## 验收标准

1. 用户能在桌面端保存一个真实节点 profile，并明确看到受支持的 token 文件要求（绝对路径、权限 0600）；界面不接收或展示 token 内容。
2. “认证检查”能显示 DNS/TCP、TLS、登录、能力和数据面检查的真实状态；登录未执行或后端不支持时显示 pending/unsupported，而不是 passed。
3. 认证成功只能在 core 返回真实 authenticated 结果时出现；失败包含可执行的修复提示。
4. 现有 demo、真实传输、schema、Python 合同和 CMake/CTest 门禁保持通过。
5. 改动限定在本任务允许路径，并提交到 branch codex/AUTH-UI-01，推送后回读远端 SHA。
