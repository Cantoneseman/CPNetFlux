# V3-GRIDFTP-10G-01：约 10 GiB V3 与 GridFTP 对照

状态：执行准备。

## 范围

在 R730→R750 直连数据链路上，以同一批约 10 GiB 目录数据比较本轮 V3
（`persistent_tree`、dynamic file scheduling、8 通道、worker/tree reuse）和
真实 GridFTP。CPNetFlux 记录 compression=off 与 compression=auto；GridFTP
使用 GSI 控制认证与私密数据通道。每个系统先做 GSI/控制 smoke，再进行三次
正式传输，独立记录文件校验、线字节、wall time、CPU/磁盘空间和认证状态。

数据集固定为：4 GiB 重复内容大文件、4 GiB 随机内容大文件、约 2 GiB 混合
目录（含小文件），合计约 10.13 GiB。所有数据由确定性生成器产生，传输前后
记录 SHA-256/tree hash；实验只走 R730/R750 的普通 TCP 数据接口，不宣称
native RDMA verbs 或跨域性能。

## 非目标

- 不修改正式 CPNetFlux agent/desktop 或系统 GridFTP 服务。
- 不安装或升级系统包，不改 apt 源，不改永久防火墙、路由和认证策略。
- 不把 GSI 认证失败、磁盘不足、服务启动失败或校验失败计为吞吐样本。
- 不触碰 GridFlux-Beta、CPSS(DCC) 或其他用户项目目录。
- 不把本次直连链路数据外推为阿里云跨域或 100 Gbps 结论。

## 验收

1. 两端 GSI proxy 有效期覆盖批次并且权限为 600；GridFTP 控制 smoke 成功。
2. CPNetFlux 与 GridFTP 3 次正式传输均成功，源/目标文件数、总字节、
   SHA-256/tree hash 一致；所有失败单独归类。
3. CPNetFlux 自动压缩决策、实际 V3 模式、动态调度和 range 完成证据可回读。
4. GridFTP 命令、版本、GSI 模式、控制/数据端口和日志均在实验目录审计。
5. 实验退出后仅清理本批路径、临时凭据和本批进程；保留 JSON/CSV/日志。
6. 结果文档提交到 `codex/V3-PARALLEL-COMPRESSION-01` 并推送 GitHub。

## 允许路径与回滚

允许修改：本文件、对应 result 文档和本次实验工具（如必须）；实验输出只放
在两端 `/tmp/cpnetflux-runs/V3-GRIDFTP-10G-01/<run-id>`。可复用已核验的
版本化 CPNetFlux 二进制，不替换正式安装。回滚只停止本批 PID、删除本批
临时根目录和凭据；不 reset/clean 其他 dirty 工作区，不删除未知文件。

## 10 GiB 调度器 profile

4 GiB 文件在当前 range planner 中形成 16 个约 256 MiB range。8 通道同时
保留这些 range 时，默认 1 ms/100 Gbps admission 预算只有约 512 MiB，会在
首个大文件上拒绝合法 range。runner 因此增加显式
`--scheduler-default-rtt-ms` 参数；本批最终使用 160 ms 作为 admission 预算，使
预留上限约 4 GiB。该值只用于有界调度器预留，不改变实际链路 RTT，也不作为
性能结论。首次 512 MiB profile 的拒绝记录保留为 blocked evidence，不纳入
吞吐统计。
