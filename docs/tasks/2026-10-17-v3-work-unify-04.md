## 范围、问题与接口

- 实际 persistent dynamic tree 客户端在显式 --reconnect-attempts N 下对 transport 故障自动恢复；默认 0 保持兼容。--transfer-timeout-ms 为整笔任务预算，跨 attempt 累计。
- 同一进程 stop/shutdown/join 旧通道，重新认证控制连接，查询旧 batch 已完全退出后才建新批次。使用新 queue/epoch，未复用已永久 cancel 的旧 queue；这替代 03 任务中直接复用 queue.recover 的接线设想，保留 03 手动原语。
- 上传保持 tree manifest 中 transferId/源元数据，下载使用既有 sourcePath/size/mtime 绑定的本地 manifest；新 wire fileId/transferId 可重新发现，不将其冒称为跨批次固定身份。重建前检查已知源元数据。
- 新批次重放文件清单，接收端逐文件/range resume handshake 根据校验后的 manifest 返回明确缺失范围；已提交且可验证的目标返回空缺失清单。未知/损坏/身份不匹配直接拒绝，不能依据本地已发字节推定完成。
- attempt/connection epoch 单调增加；每次重建重新受全局 fixed/adaptive scheduler 调度，统计累计实际 payload/wire 和重连次数。此次不承诺保留上次自适应控制器学习状态。
- transport 与认证/身份/checksum/磁盘错误区分，后者不自动重试。总 deadline 包含建连、握手、批次退出等待和传输。

## 非目标

不做通用单文件 CLI 自动重连、静态/per-file 编排自动重连、进程重启恢复服务、并发同路径多任务冲突治理、十链路/高带宽性能结论或生产 readiness。用户取消进程不启动后台重试任务。不得操作历史 dirty 树或其他项目。

## 开发与验收顺序

1. 留存基线与行为红灯：现有客户端在真实传输连接中断后失败，或重试参数尚不支持；编译错误不作为行为红灯。
2. 添加 typed transport 分类、受总 deadline 限制的连接、显式选项及批次退出屏障，恢复握手支持已提交上传。
3. loopback 行为矩阵：upload/download、fixed/adaptive、range、TLS、中断/结果丢失、不可恢复错误/预算耗尽/总 deadline。比较 SHA-256、实际 payload 和重连/epoch，不仅查 exit code。
4. 固定提交 Release/TLS/io_uring build，全量 CTest。准确记录 fail/skip。
5. 两台阿里云深圳/上海互传：双向真实 CPNetFlux 数据通路，固定二进制 SHA-256；隔离控制/数据端口与目录，受控代理仅中断本任务连接；SHA-256/manifest/缺失补传/重连证据，基线与中断恢复分别记录。SSH/scp 仅部署/取证，不能替代待测 payload。
6. 两端磁盘保留 >10 GiB，预计本阶段峰值 <2 GiB/端。仅停止本任务保存 PID 的进程；保存证据后清理本任务可再生 payload。
7. 每可审查阶段明确路径提交、push 并回读远端 SHA；完成后更新结果、BOARD、00 回执及下一步。

## 补充范围

为总 deadline 覆盖 TLS handshake，允许修改 include/cpnetflux/core/io/tls_socket.h 与 src/core/io/tls_socket.cpp；为 TransportError 分类一致允许 src/core/metrics/error_code.cpp。当前同步 DNS 解析不能被 deadline 中断；本阶段两云使用数字 IP，解析返回后重新检查剩余预算。该限制不作为硬 DNS 超时已交付。

为避免远端校验错误被其他通道断线遮盖，允许修改 persistent_directory_batch.h/.cpp，提供首个错误的类型查询；DRAIN 保留终止错误摘要，禁止再次发送 payload。

自动恢复要求 checksum 非 none，避免将无法验证的已提交文件当成可靠对账；默认 CRC32C 不变。双云使用 TLS+临时 token，所有 range 场景 fixture 为 64 MiB（严格超过两通道 32 MiB 阈值）。
