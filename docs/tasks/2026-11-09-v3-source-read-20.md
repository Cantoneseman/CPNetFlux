## Mechanism And Measurement Contract

- Runtime currently resizes/reuses a vector, reads each <=65532-byte frame into it,
  scans frame CRC32C and combines it into the range CRC, then moves the vector
  through the queue. Ordinary TCP uses scatter/gather sendmsg and still copies
  the payload into the kernel. Queue move is not itself a payload copy.
- Probe has synchronous CRC consumption only: no queue, socket, receiver,
  checkpoint or publication. It cannot demonstrate TCP zero-copy or file throughput.
- Source is an existing immutable regular file, opened O_RDONLY/CLOEXEC/NOFOLLOW,
  length 1..1GiB. Worker ranges partition at 1MiB boundaries (last may be partial),
  1..4 workers with nonempty ranges. Benchmark never deletes/modifies the source.
- A separate full-range CRC scan through 1MiB pread buffers provides expected
  digests and source residency before service. It never prepopulates candidate PTEs.
  Its setup CPU/wall/faults are reported outside service.
- Service begins before opening/checking the source, includes worker/thread/buffer
  creation, real Posix file wrapper/stats, frame CRC and range combine, mmap/first
  PTE faults/unmap, range digest checks, final descriptor/path identity/size/mtime/
  ctime checks and close. No per-frame clock sampling. Source cleanup is external,
  separately timed, never counted as an optimization benefit.
- Mapping is PROT_READ only, MAP_SHARED; no population, huge-page or caching advice.
  At most one 64MiB window per worker, and close each window before replacement.
  Spans expire before a window is replaced. No asynchronous borrowing supported.
- Check source identity before and after the scan/service; this detects many source
  changes, not a snapshot or concurrent-truncate protection. SIGBUS remains fatal
  to the isolated opt-in diagnostic (core dumps disabled). Runtime pin design remains open.
