# CPNetFlux 五角色任务章程

状态：已批准作为下一阶段 Codex 任务的共同边界。所有角色从提交 `3b0820d` 开始，不在云端正式源码树写入代码。

## 1. 架构与需求负责人

目标：把控制连接复用重测结论转成可执行的目录数据面路线。

必须阅读：`docs/RESEARCH_BASELINE.md`、`docs/DECISIONS/2026-09-17-retest-route-reset.md`、`docs/ROADMAP.md`。

输出：阶段目标、非目标、接口边界、验收指标和新的决策记录。不得直接修改实验结果来迎合路线。

## 2. 实验与证据负责人

目标：使用固定提交和 `control_reuse=worker` 补足代表性小矩阵，记录每个 case 的命令、环境、hash、wire accounting、证据完整性和资源清理。

输出：原始 CSV/JSONL、实验环境、失败分类和中文结论。不得把资源不足、观测缺失或审计器错误写成数据错误。

## 3. 核心实现负责人

目标：只实现已批准的低风险改动；当前优先方向是目录阶段可观测性和数据通道开销。

输出：独立提交、相关 CMake/CTest、性能影响说明。scheduler 和 hot-path compression 在没有阶段证据前保持隔离。

## 4. 测试与质量负责人

目标：检查 transfer status、integrity status、evidence status 和 wire accounting 的独立性，并审查每个候选优化是否改变正确性或恢复语义。

输出：测试矩阵、失败复现、代码审查意见和 go/no-go 结论。不得以单次吞吐提升替代稳定性证据。

## 5. 云端运维与发布负责人

目标：创建固定提交的隔离构建，检查磁盘和残留进程，执行实验后的清理与归档。

输出：构建 commit、二进制 hash、运行命令、结果路径、磁盘前后状态和清理证明。不得触碰 `/root/projects/CPSS(DCC)`，不得把正式云端工作树当开发分支。

## 交接顺序

架构负责人先写任务边界；运维负责人准备固定构建；实验负责人运行并归档；质量负责人审查证据；架构负责人根据证据更新路线；实现负责人只在决策记录确认后开发。任何角色发现路线错误，都可以暂停当前任务并要求更新 `docs/DECISIONS/`。
