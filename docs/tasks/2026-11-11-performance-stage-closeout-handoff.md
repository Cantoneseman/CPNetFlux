## 剩余交付 A：一个有界的发送节奏候选

承接 Task49；假设为平滑发送可能降低接收压力，目前没有证实包突发是根因。
先读实际发送入口，明确任务局部 pacing/背压是否能生效及其范围。
不能把“设置了 socket 参数”当作已改变发送节奏；需要运行时读回/机制计数或合适的发送行为证据。
若生效依赖未经授权的系统 qdisc/NIC/IRQ/RSS/THP/swap 变更，当前路线不能执行该依赖，
也不能把无效设置跑成性能实验。

实现限定为一个显式、默认关闭、可撤回、总预算不增长的候选；避免多层计时/线程池扩大复杂度。
实施前在任务记录定稿范围、非目标、受影响文件、预算、支持矩阵、退出与公平/取消行为。
保持 V3 CRC、attempt/lease、checkpoint、恢复、发布和终态；不通过少校验或扩大缓冲换吞吐。

顺序：机制/相关行为测试 → R1 固定实现提交 → 两端同提交同配置构建/二进制 SHA →
一次不超过 1 GiB、有既有停止门的可行性验证。
资源前置失败则不发 payload；任一 OOB/missed 或资源事件即停止后续实验并保留失败证据。
单次无事件不证明长期稳定；先证明机制存在，再谈性能。
最多一轮原型和一轮有具体原因的修正；安全缺陷修复或撤回不受此数量限制。
不继续 lane/profile/GridFTP 矩阵，不扫描 DATA 大小、队列深度或接收线程。

交付结论必须区分：
- 机制有效且有合规收益依据：进入 B；
- 只靠降速减少异常：报告稳定性/吞吐代价，不算性能提升，可显式保留为调试能力但不改变默认；
- 无效/退化：撤回候选或保留明确关闭的诊断能力，给出证据；
- 无法在既有环境门下验证：BLOCKED，列出最小外部条件，不伪造新性能结论。
一次同类异常已触发停止后，不以换数据量/更少并发/换计数基线绕过门重跑。
