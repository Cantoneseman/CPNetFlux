## Measured hypothesis
Three fixed f7dc827 baseline samples: producer waits 11800/12501/12403 per GiB; receiver voluntary context switches 11978/12668/12578; writer wall 0.357-0.362 s vs manifest 0.0049-0.0052 s. Separate strace sample passed integrity but is excluded from performance medians: reader 26472 and writer 14794 futex entries, writer 17408 pwrite64 calls. Trace perturbs scheduling; syscall elapsed is not untraced CPU attribution.
Hypothesis: draining the existing bounded queue before waking a blocked producer reduces receiver handoff/context-switch CPU. Implement an explicit internal AvailableCapacity/EmptyQueue wake policy, keep sender existing behavior, receiver default to be chosen by controlled same-commit A/B. No larger queue, new copies, busy spinning or coalesced writes. Diagnostic receiver environment selects available/empty for comparison and records effective policy.
