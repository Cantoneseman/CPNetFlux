# V3-RANGE-01：动态大文件 range 调度

日期：2026-10-11；状态：已实现，待提交核验

## 目标

在已推送的 V2 persistent tree 与 V3 动态文件队列之上，补齐大文件的多连接 offset range 传输。小文件保持文件级并行；只有自适应规划器判断收益足够时才拆分 range。range 使用同一 transfer_id、稳定 generation 和显式 range_id，接收端按 offset 写入同一个临时文件，全部 range 校验并持久化后才发布目标文件。

## 范围

- 增加基于文件大小、chunk size、通道数、RTT/BDP 估计和调度开销的可测试 range planner。
- 扩展持久树帧/元数据，携带 range_id、range_offset、range_length、range_count、attempt，并保留旧的 file-level 帧兼容。
- 单文件多连接路径复用同一自适应 planner；DATA 与 ChunkComplete 使用同一 range_id/attempt canonical identity，ChunkComplete 保留 32 字节旧格式并以 48 字节扩展承载新身份。
- 增加 range resume response；发送端只发送接收端声明缺失的 range，已完成 range 以安全 skip 方式确认。
- 接收端用共享事务按 offset 写临时文件，拒绝身份不匹配、越界、重复或重叠提交；全部 range 完成后复用现有 manifest/atomic publish 流程。
- 动态目录中小文件继续由有界元数据队列领取；大文件 range 按稳定计划分配到空闲数据通道，通道取消/断线时批次整体回收。
- 增加单元、loopback 和大文件 range smoke；按现有定向测试、全量 CTest、dense/mixed/large 顺序验证。

## 非目标

- 不修改桌面端、V1 源码删除、TLS、GridFTP 或深圳—上海实验。
- 不把 loopback 吞吐结论外推到跨域网络。
- 不为小文件引入切块成本，不缓存完整文件内容，不把范围调度扩展成新的独立状态语义。

## 验收

1. planner 对小文件返回 file-level，对大文件返回有界、无重叠、覆盖完整文件的 ranges，并在通道/BDP/磁盘参数变化时调整阈值。
2. frame/session 单测覆盖 range identity、resume missing ranges、skip、越界、重复、checksum mismatch 和 generation/file identity 拒绝。
3. loopback 上传、下载、resume 只重传缺失 range，最终 tree hash 和 manifest 为 committed。
4. 现有 V2 文件级、动态队列、静态队列、旧 V1 显式路径回归保持通过；单文件新格式与旧 32 字节 ChunkComplete 载荷均可验证。
5. 提交只包含本任务明确文件，push 后 ls-remote 回读与本地 commit 一致。

## 当前边界

- 单文件与目录已经共享自适应 range planner、帧头 range_id/attempt、完成载荷 canonical range identity、checksum/resume/重复提交校验语义；目录路径使用 V3 FILE_BEGIN/DATA/FILE_END，单文件路径保留 SessionInit/DATA/ChunkComplete 作为显式 V1 兼容 fallback。
- 本阶段不删除 V1 控制状态机，也不把两种 wire 版本伪装成同一历史载荷；下一阶段若要删除 V1，必须单独完成使用者审计、兼容门和删除任务。
